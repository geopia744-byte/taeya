# 다국어 리포스팅 공장 — 기획 명세서

> 유튜브 영상 캡쳐 8장을 역분석해 정리한 명세.
> 원본 툴을 그대로 베끼는 게 목적이 아니라, **같은 문제를 더 잘 푸는 것**이 목적이다.

작성일: 2026-08-27

---

## 1. 한 줄 정의

> 해외 인스타 게시물을 캡쳐해 넣으면 → 사진을 영화처럼 다시 만들고 →
> 한/일/영 각 문화에 맞는 후킹 제목을 새로 써서 얹고 → 캡션·해시태그까지 붙여 →
> 100장이든 한 번에 뽑아주는 **다국어 리포스팅 공장**

---

## 2. 핵심 통찰 — 이건 번역기가 아니다

역분석 과정에서 확인된 가장 중요한 사실. 이 엔진은 **번역기가 아니라 카피라이터**다.

### 근거 A — 원문에 없는 문장이 생성된다

| 영어 원문 | 한국어 결과 |
|---|---|
| MEXICO HAS A REAL LIFE 'BATMAN' HUNTING DOWN THIEVES AT NIGHT | 멕시코에 나타난 **현실판 배트맨** |
| BELUGA WHALE ESCAPES RESEARCH FACILITY AND SWIMS HUNDREDS OF MILES BACK TO HER BABY | 탈출한 벨루가의 **기적** / 새끼 찾아 수백 마일 |
| CHILD R\*PIST SHOT D3AD MOMENTS AFTER BEING RELEASED FROM PRISON | 출소 직후 총격 사망 / **그를 기다린 건 자유가 아니었다** |

- `그를 기다린 건 자유가 아니었다` → 원문에 **없는 창작 문장**
- `기적` → 원문에 **없는 감정 단어**
- 배트맨은 반대로 "밤에 도둑을 쫓는다"를 **통째로 삭제** (정보를 덜어내야 더 궁금해짐)

### 근거 B — 언어마다 그 문화의 후킹 문법을 쓴다

같은 벨루가 기사:

| 언어 | 결과 | 접근법 |
|---|---|---|
| 한국어 | 탈출한 벨루가의 기적 / 새끼 찾아 수백 마일 | 3인칭 서사 |
| 日本語 | 「わが子に会いたい」施設を脱走したシロイルカ | **고래의 1인칭 대사** |

일본어판이 쓴 일본식 관용:
- `「 」` 카기캇코 — 일본 매체의 인용·강조 괄호
- `！？` — 일본 특유의 물음표+느낌표 결합
- 1인칭 대사로 시작 — 일본 TV·주간지 헤드라인 정석

같은 사건(출소 직후 총격)도 문화별로 후킹 포인트가 다르다:
- 🇰🇷 `그를 기다린 건 자유가 아니었다` → **감성적 반전**
- 🇯🇵 `法に代わる「復讐」の正義` → **사회적 논쟁**

### 근거 C — 목록에 English가 있다

원본이 영어인데 출력 언어로 English를 고를 수 있다.
번역기라면 무의미한 선택지. 즉 **같은 언어 안에서도 후킹만 일어난다.**

### 후킹의 원리

> **다 말하지 않는 것.**

원문은 다 말해서 실패하고, 변환문은 절반만 말해서 성공한다.
좋은 후킹 문구는 정보를 *더하는* 게 아니라 *가려서*, 나머지를 보려면 멈추게 만든다.

## 3. 화면 구조

### 3.1 왼쪽 설정 패널

| # | 항목 | 형태 | 값 |
|---|---|---|---|
| 1 | 작성 언어 설정 | 드롭다운 | **한국어 / 日本語 / English** (확정 범위) |
| 2 | 처리 모드 | 2버튼 | `✂ 텍스트 제거` / `✨ 새로 생성` |
| 3 | 로고 설정 | 업로드 | 로고 이미지 업로드 (**선택 사항**) |
| 4 | 로고 위치 | 3버튼 + % | `왼쪽` / `중간` / `오른쪽` + 크기(예: 40%) |
| 5 | 데이터 입력 | 4버튼 | 갤러리에서 선택 / 폴더 업로드 / ZIP 파일 업로드 / 목록 비우기 |
| 6 | 전체 가이드 (콘셉트) | 텍스트영역 | 예: `20대 타겟, 절망적 카드뉴스, 유머러스한 말투` |
| 7 | 스타일 샘플 (학습 예시) | 텍스트영역 | `[제목] … [본문] …` 형식의 톤 학습용 few-shot |
| 8 | 실행 | 버튼 | `⚡ 1:1 이미지 순차 변환` (처리 중엔 `⚡ 처리 중...`) |
| 9 | 내보내기 | 버튼 | `전체 ZIP 다운로드` |

**주의**: 언어를 日本語로 바꿔도 6·7번은 **한국어로 써둔 게 그대로 먹혀야 한다.**
사용자가 일본어를 못 해도 "20대 타겟, 유머러스한 말투"라고 한글로 적으면
AI가 그 톤을 일본어로 구현해야 함. 안 그러면 다국어 운영이 불가능.

**조건부 노출**: 로고 위치(4번)는 로고를 업로드해야 나타남.

### 3.2 카드 구조

```
┌────────────────────────────┐
│              [로고]    🗑   │  ← 위치·크기 설정 따름
│                            │
│      [처리된 이미지]         │
│                            │
│   후킹 제목 (2~3줄)          │  ← 이미지 위 합성
├────────────────────────────┤
│ ① [🖼썸네일] [+] 추가        │  ← 캐러셀용 추가 이미지
├────────────────────────────┤
│ ② 생성된 본문 (원본) [📋COPY]│
├────────────────────────────┤
│ ③ ┌────────────────────┐   │
│   │ 캡션 문장 + 이모지    │   │  ← 편집 가능 (커서 확인됨)
│   │                     │   │
│   │ #해시태그 #묶음       │   │  ← 한글+영문 태그 혼용
│   └────────────────────┘   │
├────────────────────────────┤
│ ④ [🔤 글꼴 스타일 및 위치 조정]│
├────────────────────────────┤
│ ⑤ [↻ 재생성] [📄 직접 넣기]  │
└────────────────────────────┘
```

### 3.3 상태별 버튼 변화

관찰됨 — 카드 상태에 따라 하단 버튼 세트가 바뀐다.

```
편집 상태 : [🔤 글꼴 스타일 및 위치 조정]
            [↻ 재생성] [📄 직접 넣기]

완료 상태 : [↩ 수동 모드로 작성] [⬇ 개별 다운로드]
```

## 4. 처리 파이프라인

```
입력: 캡쳐 이미지 N장 + (로고) + 콘셉트 + 스타일 샘플 + 언어
  │
  ├─ 인스타 UI 제거 (하트·댓글수·계정명·캡션 잘라내고 사진만 추출)
  │
  ├─ [1단계] 이미지 처리          → 카드에 "ANALYZING..." 표시
  │    ├ ✂ 텍스트 제거 : 원본 사진 유지, 박힌 영어만 제거
  │    └ ✨ 새로 생성   : 기사 내용 기반으로 사진 자체를 AI 재생성
  │
  ├─ [2단계] 문구 생성            → 카드에 "대기 중..." 표시
  │    ├ 제목 → 이미지 위에 합성
  │    └ 본문 → 카드 아래 캡션 영역 (문장 + 해시태그)
  │
  └─ 출력: 전체 ZIP / 개별 다운로드
```

**두 단계가 카드마다 별도로 진행된다** — 이미지가 처리되는 동안 문구는 `대기 중`.

## 5. 원본 툴의 결함 — 우리가 고칠 것

### 🐛 결함 1: 한글 줄바꿈이 단어를 쪼갠다

실제 결과물에서 관찰됨:

```
그를 기다린 건 자유가 아니
었다                        ← "아니었다"가 두 동강
```

`글꼴 스타일 및 위치 조정` 기능이 있는데도 이 상태로 영상에 나갔다.
**조정 기능이 있어도 기본값이 나쁘면 100장을 일일이 손봐야 한다** —
배치 처리가 목적인 툴에서 치명적.

**해결**: 어절 단위 줄바꿈 강제(`word-break: keep-all`) + 글자 수에 따른 자동 크기 조절.
손 안 대도 되는 기본값을 만든다. 조정 기능은 그 위에 얹는 보험.

### 🐛 결함 2: 이미지가 매번 새로 생성된다

한국어판 배트맨(어두운 뒷골목)과 일본어판 배트맨(FARMACIA 간판 앞)이 **다른 사진**.
벨루가·출소남도 마찬가지. 언어마다 이미지를 새로 만들면 **비용이 언어 수만큼 배가된다.**

**해결**: `이미지 재사용` 옵션 추가 — 첫 언어에서 만든 이미지를 나머지 언어가 공유.
문구만 새로 뽑으면 되므로 비용이 1/N.

조정 가능 항목: **글꼴 / 크기 / 위치**

## 7. 구현 판단

| 기능 | 가능 여부 | 비고 |
|---|---|---|
| 이미지 업로드 (폴더/ZIP/100장 배치) | ✅ 확실 | |
| 인스타 UI 제거 | ✅ 확실 | |
| 원본 영어 문구 읽기 | ✅ 확실 | 비전 모델 |
| 한/일/영 후킹 카피 재작성 | ✅ 확실 | 핵심 강점 |
| 캡션 + 해시태그 생성 | ✅ 확실 | |
| 한글 합성 (어절 줄바꿈·자동 크기·위치) | ✅ 확실 | 결함 1 해결 |
| 로고 오버레이 (위치·크기 %) | ✅ 확실 | |
| 글꼴·위치 편집 UI | ✅ 확실 | |
| ZIP / 개별 다운로드 | ✅ 확실 | |
| **이미지 재생성** | ⚠️ 조건부 | 이미지 생성 API 키 + 장당 비용 필요 |

### 단계 전략

```
1단계  ✂ 텍스트 제거 모드   → API 키 없이, 비용 0으로 동작
2단계  ✨ 새로 생성 모드     → 키 연결하면 켜지는 옵션
```

1단계만으로도 "영어 제거 + 한/일/영 후킹 문구 + 캡션 + 해시태그"가 전부 동작한다.
2단계는 스위치처럼 얹어 비용을 사용자가 직접 통제.

## 8. 유의사항

- **저작권**: 원본 게시물의 사진은 해외 계정 저작물. `✨ 새로 생성` 모드는 사진을
  새로 만들므로 이 문제가 상당 부분 해소되지만, `✂ 텍스트 제거` 모드로 운영할 때는
  출처 표기나 사용 허락을 챙기는 편이 안전하다.
- **비용**: 이미지 재생성은 장당 과금. 100장 × 3개 언어 = 300장이 될 수 있으므로
  이미지 재사용 옵션이 사실상 필수.

---

## 9. 확정된 범위

- 언어: **한국어 / 日本語 / English** 3개
- 배치 규모: 최대 100장 상정 (큐잉·재시도·진행률 필요)
- 실행 환경: **데스크탑 Claude Code 권장** (로컬 이미지 폴더 접근, 앱 실행 확인 용이)

## 10. 아직 확인 못 한 것

- `🔤 글꼴 스타일 및 위치 조정` 패널의 실제 UI (기능은 파악됨: 글꼴·크기·위치)
- `📄 직접 넣기` 버튼의 정확한 라벨 (`작업 넣기`일 가능성 있음)
- `생성된 본문 (원본)` 의 `(원본)` 이 정확한 표기인지
- 글자 위치가 자동 배치인지 수동 조정 결과인지

→ 모두 없어도 구현에 지장 없음. 더 나은 설계로 대체 가능.
